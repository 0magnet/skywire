# skywire cli skychat channel

[← skywire cli skychat](../README.md)

Serve skychat to Claude Code as an MCP channel on stdio.

Every inbound group message and DM is pushed into the Claude Code session as
a notifications/claude/channel event. Claude answers with the reply tool, and
can read earlier messages with history and list groups with groups.

The visor is reached over its RPC, so --via dmsg://<pk> or skynet://<pk> runs
the channel as that remote visor's identity. A dropped session reconnects
with backoff, and a state file resumes the stream without replaying history.

Load it in Claude Code from .mcp.json:

  {"mcpServers": {"skychat": {"command": "skywire",
    "args": ["cli", "skychat", "channel"]}}}

  claude --dangerously-load-development-channels server:skychat

Stdout carries the MCP protocol only; diagnostics go to stderr.

## Usage

```
skywire cli skychat channel
```

## Flags

```
      --dms[=true|false]       deliver direct messages too (default true)
      --groups strings         group ids to deliver (default every group this visor is an active member of)
      --ignore-prefix string   drop inbound messages starting with this (default "[claude bot]")
      --prefix[=true|false]    start every reply with "[claude bot]"; turn off when the channel has a visor key of its own (default true)
      --rpc string             visor RPC address (with --via, the local visor that bridges to the remote one) (default "localhost:3435")
      --senders strings        only deliver messages from these public keys (default every sender)
      --state string           resume state file (default <user config dir>/skywire/skychat-channel/<local|pk>.json)
```
